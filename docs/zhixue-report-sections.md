# 智学网附加报告

智学网继续使用现有官方网页登录会话（SecureStore 中的认证信息），由设备直连官方报告服务。无需 root，不读取官方 App 的私有数据，不增加业务后端。

## 当前接入范围

在现有成绩详情与单科详情的 `reportSections` 中展示：

- 全科、单科近五次成绩变化：班级、学校及平台提供的联考范围合并为一张卡片，总结以“【班级】”“【学校】”“【联考】”标注；没有预估排名时，同范围等第与人数两列显示；有有效预估排名时三列显示。同时间、同名称的考试合并各范围明细，各范围占一行，等第、变化、人数三列等宽，缺失字段显示破折号。按时间排列，移除等级划分规则说明。
- 全科学科诊断：默认只展示学科水平雷达图，官方建议和 T 分说明展开后放在卡片底部，不再展示逐科评价。各学科作为坐标轴，展示本次、平时及班级中等水平；官方只提供年级参照时标为年级中等水平。网格从 100 至 0 分为六级（100、80、60、40、20、0），绘制各级网格和零点，不标数字。平时与本次全部原始数据及缺失位置完全一致时隐藏平时曲线和图例。缺失值保留空缺，不补零或绘制跨缺失项的闭合区域。
- 单科知识点掌握说明：保留官方列名和数据；明细表为空时仍展示已有的概述与建议，不额外显示“平台暂未提供知识点明细”。

近五次成绩变化的班级、学校、联考总结默认隐藏，展开后显示在顶部指标之后、历史考试明细之前。学科诊断的说明仍放在该诊断卡片底部。

趋势展示名称使用“班级等第”“学校等第”“班级人数”“学校人数”“联考人数”；人数卡片的数值后不再附加“人”。明细与总结使用“等第”“学校”“人数”。这些是文案变更，仍读取同一官方 `clazz/grade/union` 数据，保留原始等第、人数与变化值。

排名预估仅在当前考试、当前学科及相应范围的规则得到确认时显示。趋势响应的 `scoreLevelType=score` 表示分数型，直接隐藏排名；未知类型也不显示。`number` 或未返回该字段时，仍必须进一步取得 `/zhixuebao/report/common/rulesAndCopywriter`，确认 `ruleObtainType=2` 且 `leveType=NUMBER`。不能将趋势接口的 `levelList` 单独当成人数百分位。

规则请求绑定 `examId`、范围 `code=clazz/grade/union` 和 `subjectCode`（总分为 `00`）；不读取或信任响应中的任意跳转地址。语文使用 `01`。顶部等第、人数及预估排名优先按当前考试 ID（单科为试卷 ID）精确选择记录，不取其它历史考试的最新记录；当前记录缺失时保留历史明细，不生成该范围的当前指标或总结。

联考范围不借用班级或学校人数。当前联考记录与范围概览的 `statTotalNum` 一致时采用统计人数；没有可确认的统计人数时，仅在当前记录 `totalNum` 与概览 `totalNum` 一致、且记录内统计人数不冲突时采用该联考人数。仍无法确认时人数显示“—”，明细不填入未经确认的人数，不预估联考排名，并在折叠说明中解释口径问题。联考历史记录没有同场概览可验证时，不套用当前联考概览人数。

明确按人数比例划分时，官方说明页直接将规则区间显示为 `(lowBound%, upperBound%]`，不再做 `100−区间` 转换。使用该规则的等第区间和本次 `statTotalNum=N`，下界为 `floor(N × lowBound/100)+1`，上界为 `floor(N × upperBound/100)`，限制在 1 至 N 内。例如 700 人、已确认的人数型 B 等区间 `(15%,30%]` 对应 106~210。缺少人数、零人数、无有效整数名次、格式异常、区间重叠、重复等第或接口失败时，隐藏对应排名卡片，不显示破折号或借用其它范围的规则。会话失效和请求取消仍向上抛出。

有有效排名时与等第、人数同排三列，排名标题单行并自适应字号；没有排名时该范围恢复两列，各范围独立成行。

四类附加报告使用考试官方路由，限定 `www.zhixue.com` / `ali-bg.zhixue.com`，接口前缀为 `/zxbReport/report/`。等级规则使用固定主站 `https://www.zhixue.com`，路径单独列出；均复用现有 `XToken/token/auth*` 请求头：

| 场景 | 路径 | 参数（不含认证头） |
| --- | --- | --- |
| 全科趋势 | `exam/getLevelTrend` | `examId,pageIndex=1,pageSize=5,startSchoolYear,endSchoolYear` |
| 单科趋势 | `paper/getLevelTrend` | 上述参数 + `paperId`，可用时附 `subjectCode` |
| 全科诊断 | `exam/getSubjectDiagnosis` | `examId` |
| 单科知识点 | `paper/getExamPointsAndScoringAbility` | `examId,paperId` |
| 等级规则（固定官方主站） | `/zhixuebao/report/common/rulesAndCopywriter` | `examId,code,subjectCode` |

学年边界来自考试 ID 中已绑定的官方学年上下文，不用当前年份覆盖历史考试。

## 展示与失败策略

按用户要求，**不请求或依据 `getModules` 决定展示**。直接读取相应只读数据，验证成功且有实际内容则生成卡片。成功但内容为空、未开放或不存在时不生成该部分；有文字但没有表格行仍可显示文字。网络或格式异常提供刷新提示，不清空已有分数和其它成功报告。

发挥水平学科诊断在网络或格式异常时也隐藏卡片，不展示附加报告加载失败提示。会话过期、取消请求不降级为普通空报告。获取报告后再次核对当前家长和学生，防止服务端学生选择变化后展示其他学生数据。附加报告内容交给现有 TanStack Query 管理，不增加第二份 Provider 内容缓存。

## 字段语义

- 趋势明细只展示 `statTotalNum`（界面标为“人数”），不重复展示 `totalNum`。不能单凭人数或分数型等第推算名次；仅在上述人数比例规则确认后估算范围，不作为官方实际排名。
- 诊断 `myRank/avgRank/rationalRank` 按官方前端以 `100 - 原值` 转为图示水平刻度，界面明确不等同于分数、实际名次或击败率。
- `showGradeSecondary=false` 时保留“平时水平”和“班级中等水平”；为 true 时使用“年级中等水平”，不显示平时水平。
- 知识点 `name/score/myScoreAbility` 对应官方表格的知识点、权重、掌握程度。只给明确返回的合法掌握程度添加 `%`；缺失值不转成 0。

## 验证

### 历史真实请求

2026-10-16 使用用户已有官方浏览器会话，先核对当前学生，再以与 Provider 相同的认证头验证全科趋势、单科趋势、全科诊断、单科知识点四个接口，均成功返回。本地执行实际 `createZhixueProvider`（仅将 Expo 加密适配为等价的 Node MD5/UUID；HTTP 为真实 fetch），完成 15 次只读请求，未请求 `getModules`。当时班级、年级趋势分为两张卡片，因此全科、单科各产生 3 张；这是合并前的历史结果。

### 当前实现及未验证项

趋势合并后，在相应内容均可用时，全科为“趋势 + 学科诊断”两张卡片，单科为“趋势 + 知识点说明”两张；空内容或不可用诊断会减少卡片数。

首次复查从已保存的原始响应确认总分和语文的 `scoreLevelType=score`，按当前逻辑隐藏预估排名。当时用户信息请求返回 HTTP 200 空响应，未取得新的等级规则响应，因此该轮尚未验证人数型分支。等级规则的类型与区间含义另依据官方说明页及脚本核对；后续重新登录后的真实人数型验证见下方“联考适配复核”，不能把两场考试的类型或阈值混用。

提交 `fdcf071` 对应实现已通过 lint、typecheck、全量测试及 Android Hermes 导出。虚构数据回归覆盖分数型与未知类型隐藏排名、人数型规则确认、范围独立失败、当前考试/试卷匹配、人数及区间边界、会话失效和取消；组件测试覆盖总结折叠、分行布局及雷达图内容。Android 真机的卡片滚动、展开、雷达图标签与布局仍待人工验收。

### 联考适配复核（2026-10-17）

用户重新完成官方登录后，执行实际 Provider 读取指定联考的全科报告及官方主报告返回的语文、物理两个科目，最终复核共 33 次只读请求，读取前后核对当前学生，没有请求 `getModules`。全科与两个单科趋势响应均返回 `scoreLevelType=number`，各范围规则均为 `ruleObtainType=2`、`leveType=NUMBER`；该样本的 A/B/C/D/E 人数区间为 0–5%、5–10%、10–20%、20–40%、40–100%，不沿用其它考试的阈值。

全科联考记录与概览人数一致，已取得联考人数和预估范围；语文、物理的单科联考记录人数与联考概览冲突，保留联考等第与变化，人数显示“—”并隐藏联考排名。全科学科诊断返回 40201，按已有失败策略隐藏。原始响应、签名地址和映射结果仅保留在 Git 忽略目录，真实接口映射通过不代表 MuMu 布局及交互已验收。

联考适配后的工作区通过 lint、typecheck、全量 44 套 580 项测试及 Android Hermes 导出。新增虚构数据回归覆盖三范围合并、当前记录选择、联考人数一致性、独立规则失败与联考明细分行展示。
