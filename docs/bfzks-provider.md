# 百分智 Provider

科目详情已支持客观题、主观题得分/满分汇总，复用睿芽解析并分别核对官方脚本及授权账号响应。仅在逐题数据完整且得分合计与原始分一致时汇总，赋分不参与差值推算；数据不一致时保留明细。字段规则与当前验证范围见 [题型汇总接入](question-score-summaries.md)。

- 平台名称：百分智考试服务云平台
- 官方域名：`https://www.bfzks.com`（报告数据在 `http://bfzks.xueqingroom.cn`）
- 登录方式：官方报告查询登录页的账号密码流程（`hndSystem=1`，报告查询类型）；密码按官网前端 RSA 方式加密，会话 Cookie 仅保存在设备。
- 登录链路：`POST https://www.bfzks.com/` → `302 http://bfzks.xueqingroom.cn/Login.aspx?signature=…` → `302 /report/test/`。
  会话 Cookie（`UserSign`/`LoginName`）由**中间 302** 下发，且为 host-only，只对 `bfzks.xueqingroom.cn` 生效。
- 会话保存：Provider 以 `platformCookieJar: true` 运行——会话 Cookie 交给系统 Cookie 容器跨重定向携带，请求不手工附加 `Cookie` 头，注销时清空容器。
  原因：React Native 的 `fetch` 忽略 `redirect: 'manual'`，重定向在原生层自动跟随；若用 `credentials: 'omit'`（OkHttp `NO_COOKIES`），中间响应下发的 Cookie 会永久丢失，
  登录后只能拿到未登录占位页，表现为「报告列表结构不符合预期」。
- 协议：报告主机由平台自身以**明文 HTTP** 提供（官方跳转即 http），且 `bfzks.xueqingroom.cn` 证书链不完整（未下发中间证书），无法升级为 https；Provider 沿用平台实际协议。
- 支持能力：学生信息、考试列表、成绩、班级/学校/联考排名、科目统计、题目得分和答题卡（以官方响应实际提供为准）。
- 已知限制：百分智与睿芽共用报告查询协议，但 Provider、域名和会话独立；接口未返回的满分、统计或题目字段保持缺失，不推测填充。当前只实现本人正常可访问的报告查询链路，不绕过验证码或其他访问控制。
- 答题卡：官方图片接口以 URL 中的报告签名为访问控制（实测不带 Cookie 也返回 200），Provider 仍随 `AnswerSheet.headers` 附带可收集的请求头。

## 单场考试数据与展示

百分智通过共享解析器的 `extendedReports` 配置接入扩展报告，平台差异留在 Provider 内。UI 使用统一的 `ReportSection` 模型，不判断百分智平台 ID。长内容分析默认折叠，总分分数线直接显示；对比采用带数值的横向条形图。科目排名与考试排名均采用大字号名次、小字号总人数。

| 数据 | 官方来源 | App 展示 |
| --- | --- | --- |
| 原始分、赋分、等第、标准分、各范围均分和排名 | `resultsByGroup`、`sortByGroup` | 成绩总览、科目统计；标准分保留数据但隐藏展示；赋分 `-1` 回退原始分，隐藏模式遵守 `scoreShow`/`scoreRank` |
| 缺考科目 | 官方报告 `.absent` 科目入口 | 总览缺考卡片，不提供详情操作 |
| 各科超过比例、分数线基准、优势与薄弱学科、排序 | `percentByGroup` | 学科表现卡片、本人与各条线的超过比例对比；直接使用官方百分比，不按得分除以满分计算 |
| 班级位置和上线人数分布 | `compareByGroup` | 班级位置、超过比例、A线/B线区间/未上线人数 |
| 总分分数线 | `getscorelines/{sign}/0` | 紧凑行直接显示线名、大字号分数和小字号单位，无需展开 |
| 原始试卷满分、题目数、页数、日期 | `getscorelines/{sign}/{paperId}` | 按统一展示约定，主分数（含赋分）后显示卷面满分，原始分旁不重复显示；不展示试卷信息卡片 |
| 逐题得分、满分、题型、知识点、实测难度、校/班均分 | `tsubsByGroup` | 科目题目明细；保留客观/主观分组及错题筛选 |
| 客观题本人答案和正确答案 | `tsubsByGroup` | 逐题答案，对照错误状态 |
| 主观题作答裁图 | `getOSS_CutPaper/{sign}/{paperId}/{questionId}` | 点击“查看作答”按需加载、全屏查看、长按保存 |
| 主观题参考答案、题干图 | 逐题响应的图片地址 | 有可用 HTTP(S) 图片时显示相应按钮 |
| 本人、班级、学校、总体题组得分率 | `getScoreByPaperInfoTitle` | 题组对比条形图，按 `InfoTitle` 匹配而非响应顺序 |
| 章节成绩、基准名称、等级、合计及说明 | `chartByGroup` | 知识章节以个人得分及各基准的独立进度条展示，共用章节满分比例尺，等级使用 badge；章节概览保留汇总及说明 |
| 能力总分、本人分、基准、得分率及能力说明 | `ablityByGroup` | 保留学习能力，不展示能力分析说明卡片 |
| 科目学能分、综合学能分、提分分析 | `getByAbilityScore`、`getByAbilityTotalScore` | 仅 `scoreShow=1` 展示分数，定位比例遵守 `scoreRank=1`；未开放整张卡片隐藏 |

### 数据边界

- 截至 2026-10-08，授权账号有两场可访问考试，每场六科成绩及四个缺考入口。第一场六科合计 149 条逐题数据，第二场未提供逐题数据和整卷图片。这些差异来自官方响应，不能以空数据推断零分或登录失败。
- 英语逐题得分/满分合计与官方科目原始分/试卷满分不一致，继续展示原始明细，隐藏无法核验的题型汇总。题组得分率属于另一套统计，不与逐题合计混算。
- 当前账号的单科及综合学能分析未开放。旧的 `getAbilityScore` 实测 404；官网的 `getByAbilityScore` 正常返回，但 `scoreShow=0`。扩展配置已修正接口名并遵守开放标志，失败不阻断其它报告内容。
- 裁图接口实测返回 `data:image/jpg;base64,...`；同时兼容 HTTP(S) 图片。仅接受受支持的栅格图片 Data URI，拒绝文件协议和 SVG。内嵌图片直接预览，保存时按 Base64 写入设备缓存，不重复网络下载，也不提供“复制链接”。
- 尚未确认语义的区域排名、第三基准及分数线人数/边界字段不直接展示；授权账号未提供的视频资源未扩展成播放器。广告、支付、错题修改及他人报告不在此查询范围内。
- 可选分析失败时保留基础成绩，分别显示暂不可用或未提供提示；学能未开放则隐藏卡片。离开再进入可重新请求。
- 作答图片加载及错误弹窗不显示关闭按钮，点击卡片外的空白处关闭；卡片内点击不关闭，错误状态仍可重试。

### 验证

使用虚构数据覆盖接口映射、开放标志、题组身份匹配、空题目、图片协议和缓存写入；使用 MuMu 的 ADB 页面树与必要截图验证实际授权账号的登录、两场报告、折叠分析和作答图片。真实成绩、账号、报告签名和图片均不进入 Git。

2026-10-08 首轮设备验收：题组四组对比条、章节和客观答案正常显示；缺考卡片无详情操作；主观作答图片预览成功，长按保存后系统相册图片数增加 1；第二场分别显示逐题、章节、能力及整卷答题卡缺失提示。随后按界面要求移除能力分析说明、试卷信息和未开放学能卡片。学能分的非空展示路径仅以虚构响应测试，不声称真实账号已验证。
